## Exit gate

Design §15: *KDL parse of greeter config + Spawn/SpawnSh/Quit IPC + `niri msg` **and** `sysc-compositor msg`.
greetd VT: gSlapper + sysc-greet, quit. **sysc-greet works.***

1. sysc-greet's greeter config (`sysc-greet/config/niri-greeter-config.kdl`, unmodified) parses; its
   startup commands run with the compositor's environment; its keyboard settings reach clients.
2. The compositor serves the niri-ipc socket at `$NIRI_SOCKET`. Niri's own `niri msg` (26.04, installed)
   and our `sysc-compositor msg` both get `Version`, `action spawn`, `action spawn-sh` and
   `action quit --skip-confirmation` answered, and quit ends the session.
3. **Nested, laptop:** the greeter config with `sysc-greet` switched to `--test` (it refuses to run
   without greetd otherwise) shows gSlapper's wallpaper and kitty fullscreen with sysc-greet, and
   leaving sysc-greet ends the compositor through `niri msg action quit`. `grim` shots before and after
   typing.
4. **greetd VT, laptop, unmodified config:** scheduled with the owner (see "VT gate").

## Decisions

| Item | Choice | Why |
|---|---|---|
| KDL | `github.com/sblinch/kdl-go` pinned at `v0.0.0-20260121213736-8b7053306ca6` (commit `8b70533`), no dependencies | Niri 26.04 parses KDL **v1** (`knuffel 3.2`); this library implements v1 only. It has no release tags, so the pseudo-version is the pin. Design §4 prefers a library that matches niri's dialect. |
| Config shape | `internal/config` decodes the sections M2 applies (`spawn-at-startup`, `spawn-sh-at-startup`, `environment`, `input.keyboard` xkb and repeat). The other sections Niri knows are **accepted and kept unapplied**; an unknown top-level node is an error with its line | Niri rejects unknown nodes. M3 must accept this machine's whole config, so the known-name table is the full top-level list from `niri-config/src/lib.rs`, not just the greeter's. |
| Config path | `-c`/`--config`, then `$NIRI_CONFIG` (empty means unset), then `$XDG_CONFIG_HOME/niri/config.kdl`, `~/.config/niri/config.kdl`, `/etc/niri/config.kdl`. None found: run with defaults | Design §4. Writing the embedded default config is M9, with live reload. |
| IPC wire | `internal/ipc`, pure Go: serde's externally tagged enums. Unit requests are strings (`"Version"`); `{"Action":{"Quit":{"skip_confirmation":true}}}`; replies `{"Ok":…}`/`{"Err":"…"}`; actions reply `{"Ok":"Handled"}` | `niri-ipc/src/lib.rs`, `src/ipc/server.rs:181`. |
| Unimplemented | Every request and all Action names from niri-ipc 26.4.0 decode; the ones not built reply `Err("unimplemented: <Name>")`. An unknown name is a parse error, as serde's | Design §5. A test compares the action table with `niri-ipc/src/lib.rs` when the reference checkout is present. |
| Version | `Version` replies `sysc-compositor <version> (niri-ipc 26.4.0)` | Design §6. `niri msg` compares versions only after an error (`client.rs:73`), and only prints a warning. |
| Socket | `$XDG_RUNTIME_DIR/niri.<wayland-socket>.<pid>.sock`, mode 0600, same-uid peers only, many requests per connection | Niri's name (`server.rs:81`) and loop (`server.rs:186`). The peer rule and listener are the control socket's: the listener code moves to `internal/unixsock` and both sockets use it, rather than copying 120 lines of security code. |
| Threading | Connection goroutines; `Quit` posts `Terminate`; `Spawn` does not touch wlroots | The control socket's pattern (`internal/server/control.go`). |
| Spawn | `exec.Cmd` with stdio on `/dev/null`, `~` expanded in argv[0], reaped by a goroutine. Child env: ours plus `WAYLAND_DISPLAY` (the nested socket), `NIRI_SOCKET`, the config's `environment {}`; `NOTIFY_SOCKET` and `DISPLAY` removed | Niri `spawning.rs`. Niri double-forks; Go cannot fork safely, so the child is reaped instead. Go restores the original `RLIMIT_NOFILE` in children. No activation token: xdg-activation is not a global yet. |
| `SpawnSh` | `sh -c <command>` | `spawning.rs:93`. |
| `Quit` without `--skip-confirmation` | Quits at once; matrix row `[~]` | Niri shows a confirmation dialog first. No dialog exists before the screenshot/overlay UI work. |
| Fullscreen | `set_fullscreen` before or after the first commit sizes the window to its output and places it at the output origin | `kitty --start-as=fullscreen` is how sysc-greet covers the screen. Unfullscreen, windowed fullscreen and restore stay in M6. |
| CLI | `internal/cli` serves `sysc-compositor` and a `cmd/niri` with the same `main`: no subcommand runs the compositor; `msg [--json] version`, `msg action quit [-s/--skip-confirmation]`, `msg action spawn -- …`, `msg action spawn-sh -- …`, `msg request-error`. Other `msg` forms say they are not built yet | Design §6. sysc-launch already calls `{compositor} msg action spawn -- …`. |
| `niri validate` | Not in M2 | M3's gate. |

## VT gate

The laptop's greetd runs Mango (`/etc/greetd/config.toml`). Switching it needs root, and a broken
greeter locks the owner out of the laptop's login. Before touching it, agree with the owner on:
a copy of the current `config.toml`, the new `command` line, a way back that does not need the greeter
(an SSH session kept open), and when. Nothing on the VT is changed before that.
