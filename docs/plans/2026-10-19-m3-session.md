# M3: shell session, EventStream, and config validation Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make sysc-shell start on sysc-compositor with Niri-compatible output, workspace, layer, and EventStream state, and accept this machine's Niri configuration.

**Architecture:** The compositor thread remains the sole owner of wlroots and publishes immutable Go snapshots to IPC readers. Niri requests return the pinned 26.4.0 wire shapes; EventStream sends an initial state followed by bounded per-client updates and disconnects slow clients so they can reconnect and resync. KDL includes are merged at their source positions before existing config decoding.

**Tech Stack:** Go 1.26, cgo, wlroots 0.20, niri-ipc 26.4.0 wire, pinned kdl-go, sysc-shell at origin/main.

## Task 2: EventStream initial state and bounded delivery

**Files:** internal/ipc/serve.go, internal/ipc/wire.go, internal/ipc/wire_test.go, internal/server/niri.go, internal/server/niri_test.go.

1. Add a real-socket test for the EventStream handshake, initial state order, newline framing, and a subsequent state update.
2. Add a bounded-client test showing a slow reader is disconnected and a new connection receives the current full state.
3. Implement the handshake reply first, then the Niri state replication order: WorkspacesChanged, WindowsChanged, configured keyboard layouts when available, OverviewOpenedOrClosed, ConfigLoaded, and CastsChanged as applicable. 4. Publish state without waiting on socket writes or a client's queue. Keep the queue bounded; close only the slow client's stream and let it reconnect for a fresh state.
5. Run the focused IPC and server stream tests. Confirm the compositor thread never performs network I/O.
