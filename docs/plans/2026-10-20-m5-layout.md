# M5 Scrolling Layout and Core Bindings Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add Niri-compatible scrolling columns, dynamic per-output workspaces, and the core KDL bindings needed for this machine's nested compositor gate.

**Architecture:** `internal/layout` owns column order and viewport geometry. `internal/wm` owns per-output workspaces and stable IDs. `internal/bind` parses key chords into supported actions. `internal/wlr` applies model changes to scene nodes on the compositor thread, and `internal/server` publishes Niri snapshots and events.

**Tech Stack:** Go, cgo with wlroots 0.20, KDL v1 via the installed `kdl-go`, niri-ipc 26.4.0.

---

## Scope

- Follow product contract §3 and §15. Niri 26.04 defines behavior; Mango 0.18.0 supplies wlroots patterns.
- Keep one window per column for M5. Tabs, floating windows, consume/expel, fullscreen, named workspaces, and cross-output moves remain M6 work.
- Keep one empty workspace at the end of each output's workspace list. Remove other empty inactive workspaces. Keep workspace IDs stable while their output remains connected.
- Place a newly mapped window in a new column to the right of the focused column. Keep the focused column visible in the output viewport.
- Parse and apply the M5 bind subset from KDL: close, spawn, focus/move column, and focus workspace by index. Keep unsupported actions visible as validation warnings.
- Include the M5 input findings recorded on `sysc-1270`: nested modifier selection, Mod+RMB edge resize whose width/height remain in the workspace model after release, move/resize cursor images, and cursor theme/size propagation to spawned clients.
- Keep wlroots calls on the thread that owns the compositor. Keep the layout, workspace, bind, and config packages free of cgo. Add no dependency.

## Tasks

### Resize state decision

M5 keeps pointer-resized dimensions in the in-memory layout model for the lifetime of the window.
Column width controls that window's column while M5 has one window per column; window height is
stored per window. Scene placement, requested size, and workspace snapshots are reapplied from this
model, so later focus, workspace, or output updates do not restore the default tile dimensions.
This does not write sizes to disk.
