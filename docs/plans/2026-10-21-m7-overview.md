# M7 Overview and Input Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement the M7 overview, overview IPC, three- and four-finger gestures, hot corners, tiled-window insert hints, and configured drag-and-drop edge scrolling with the Niri 26.04 contract.

**Architecture:** `internal/wm` owns overview state, workspace projection geometry, hit-testing, and drag placement decisions. `internal/wlr` owns the projection scene and all wlroots interaction on the locked compositor thread; it references live source buffers while the original xdg trees keep surface lifecycle and output tracking. `internal/config`, `internal/bind`, and `internal/server` decode and publish the existing Niri KDL and IPC shapes.

**Tech Stack:** Go 1.26, cgo, wlroots 0.20, KDL v1 via the installed `kdl-go`, niri-ipc 26.4.0, Niri v26.04 (`8ed0da44d974c32c6877d2f4630c314da0717ecb`), and Mango 0.18.0 (`a21b10fcbe6156b76ea96178d1941de5cb36137f`).

## Scope and decisions

- Follow [the approved M7 design](2026-10-21-m7-overview-design.md), product contract §15, and the M7 parity rows. Niri defines behavior and wire shapes; Mango is used only for wlroots 0.20 API and lifecycle patterns.
- Keep projection state and workspace/window geometry in pure Go. The overview uses the configured zoom and backdrop color, with the active workspace centered in a vertical workspace strip. Pointer activation uses the inverse projection and WM placements.
- Keep M7 rendering direct. M8 owns spring animations. Four-finger gestures update overview progress while moving; release chooses the open or closed state from the projected gesture position.
- Decode the M7 fields the behaviors consume: `overview.zoom`, `overview.backdrop-color`, `gestures.hot-corners`, `gestures.dnd-edge-view-scroll`, and `layout.insert-hint.off` / `color`. Defaults match Niri 26.04: zoom 0.5; hot-corner top-left when none are explicitly selected; edge-scroll width 30, delay 100 ms, maximum speed 1500 logical pixels per second.
- Use the configured one-logical-pixel corner region. `off` disables all corners. Crossing into a configured corner toggles overview once; leaving and re-entering permits another toggle.
- Start tiled moves after Niri's drag threshold. Commit the chosen insertion position on release; cancellation restores the original workspace and placement. Keep the existing direct geometry path for floating-window moves.
- Edge scrolling belongs to client data-device drag-and-drop, not the compositor's Mod+drag. Honor the configured edge dwell delay and maximum speed, and stop scrolling when the drag leaves the edge, drops, or is destroyed.
- Keep all wlroots calls on the thread that ran `runtime.LockOSThread()`. Add no dependency, handwritten `.c` or `.h` file, spring system, or shell-owned overview UI.
