# M10 Input and Idle Protocols Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Complete the M10 portion of the Niri 26.04 contract: compositor bind repeat, text input, cursor shape, session lock, idle, input constraints, and frost.

**Architecture:** `internal/wlr` owns Wayland resources, input focus, output power, and scene effects on the locked compositor thread. Keep bind repeat state in the compositor event loop. Keep the ScreenSaver service in `internal/session`, using the existing godbus dependency. The shell continues to own idle policy and presentation; the compositor reports idle and lock state and enforces its own injection boundary.

**Tech Stack:** Go, cgo, wlroots 0.20, SceneFX 0.5, wayland-protocols 1.49, niri-ipc 26.4.0, godbus 5.2.2.

## Contract and decisions

- Issue `sysc-1275` follows design §7–9, §12, and §15 plus the M10 rows in `niri-parity-matrix.md`. Niri 26.04 at `8ed0da44d974c32c6877d2f4630c314da0717ecb` defines behavior. Mango 0.18.0 at `a21b10fcbe6156b76ea96178d1941de5cb36137f` supplies wlroots 0.20 protocol and input patterns. Hyprland at `8b7aefe32e3459a6e3a92cbd6dd6c638d1b8dbdd` is used only for cached blur and damage invalidation patterns.
- Implement only behavior this milestone owns: `ext-background-effect-v1`, bound-key repeat, text-input-v3 and input-method-v2, cursor-shape-v1, session-lock-v1, ext-idle-notify-v1, idle-inhibit-v1, relative-pointer, pointer-constraints, keyboard-shortcuts-inhibit, and `org.freedesktop.ScreenSaver`.
- The shell already sends `PowerOffMonitors` and `PowerOnMonitors` for its configured blank/unblank idle actions. Move these two actions from M15 into M10 so this compositor can support the existing shell path and gate injected input while all monitors are blank. Keep output configuration, mode/scale/transform, per-output power policy, VRR, and output-management work in M15.
- `PowerOffMonitors` and `PowerOnMonitors` must preserve output layout and workspace state. Restore only outputs that this action powered off. A session lock or all-monitors-off state blocks injected input at the WLR injection methods; ordinary physical input remains available to unlock or wake the session. No socket verb may unlock or clear a user Stop.
- Input activity and idle notifications are seat0-only. Injected input must never reset user idle or wake powered-off monitors. When lock or blank state begins, release any held injected keys/buttons before accepting more injected events.
- Keep frost rendering in the existing SceneFX renderer. Apply the protocol's surface-local region on the next surface commit and damage only the affected output region. Do not introduce a custom GLES renderer or a new module dependency.
- The compositor owns the Niri-compatible `org.freedesktop.ScreenSaver` name in `--session` mode. sysc-shell currently also attempts to own this name; its consumer handoff remains part of the later suite integration (`sysc-1283`), so this milestone does not edit the sibling repository.
- The compositor implements the lock protocol and blanking behavior only. `sysc-lock` continues to own the lock UI and authentication.

## Task 3: Implement compositor-owned text, pointer, and shortcut behavior

**Files:**
- Modify `internal/wlr/keyboard.go`, `internal/wlr/input.go`, and the existing scene/surface owners.
- Extend the bind and input config types only where the existing KDL contract requires it.

1. Relay text-input-v3 state between the focused user-seat surface and the input-method-v2 client, including enable/disable, surrounding text, preedit/commit/delete, and popup placement. Do not route agent-seat focus into the input method.
2. Apply cursor-shape requests only from the focused user-seat pointer client; resolve the requested shape through the current Xcursor manager and restore the client cursor on leave.
3. Apply locked/confined pointer constraints when their surface is focused, honor region updates, and send relative motion alongside the absolute pointer update. Clear constraints when focus or the surface changes.
4. Activate shortcut inhibitors only for their focused surface, suppress compositor binds while active, and implement `ToggleKeyboardShortcutsInhibit` against the focused inhibitor as Niri does.
5. Implement repeat only for binds marked `repeat=true`. Use the Wayland event loop timer, configured delay/rate, and stop it on release or replacement. Preserve one physical key press to layer-shell clients; never synthesize compositor repeat events to them.

## Task 4: Implement lock, idle, output power and the injection gate

**Files:**
- Modify `internal/wlr` lock, output and input owners.
- Modify `internal/control` only if the compositor needs an internal held-input release operation.
- Modify `internal/server` action dispatch and `internal/ipc` only as needed for the existing decoded actions.

1. Create a lock scene above normal content. Configure a lock surface per output; keep an opaque black surface where a lock surface is absent or not yet mapped. Restrict keyboard and pointer focus to lock surfaces until protocol unlock.
2. Enter the blocked state as soon as a lock request is accepted, before acknowledging the protocol's `locked` event. Clear it only after valid protocol unlock; client destruction or missing surfaces must leave the session sealed.
3. Implement `PowerOffMonitors` and `PowerOnMonitors` as compositor-thread actions. Preserve layouts and scenes, track which outputs were active before power-off, and restore only those outputs. Handle output-power-v1 requests through the same state path.
4. Block injected key presses, pointer motion and button presses while session-locked or while all outputs are powered off. Allow release cleanup, release all held input when entering either state, and keep lock/unlock out of the control socket.
5. Notify ext-idle-notify only for real user-seat input. Aggregate idle-inhibiting surfaces and D-Bus ScreenSaver inhibition; agent-seat traffic must not postpone idle.
6. Keep physical activity and the shell's ext-idle resumed path able to wake monitors. Verify wake does not change focus, workspace, or output placement.
