# M12 Task 7: tablet tools and pads

Owner decisions (2026-10-29), after comparing pinned Niri 26.04, Mango and Hyprland:

- **Tools follow Niri.** Output mapping, aspect ratio, clamping and tip-down focus come from
  `src/input/mod.rs` (`compute_tablet_position`, `on_tablet_tool_*`) and
  `src/niri.rs` (`output_for_tablet`).
- **Pads as Mango/Hyprland do.** Niri has none. Buttons, rings and strips reach the surface the
  tablet's tool is over; the pad enters and leaves with that tool.
- **Pointer emulation for surfaces without tablet-v2**, as Mango/Hyprland (and sway) do. Niri sends
  tool events only to tablet-aware clients.

## Behavior

| Event | Tablet-aware surface, no modal UI | Otherwise |
|---|---|---|
| proximity in / axis | warp the cursor to the mapped point; proximity-in/motion and changed axes to the surface; pads enter it | warp the cursor and run ordinary pointer motion |
| tip | focus the surface under the pen (`focusSurfaceAtCursor`), tool down with implicit grab / up | the click path (`deliverPointerButton`, `BTN_LEFT`), so screenshot UI, switcher, overview, colour picker and exit dialog react as Niri's tip does |
| button | tool button | ignored, as Mango does |
| proximity out | tool proximity-out, pads leave; ordinary pointer motion at the pen's point (Niri's `move_cursor`) | ordinary pointer motion |

A tip goes up the way it went down. Modal UIs are the screenshot UI, switcher, overview,
colour picker and exit dialog. Tablets join only the user seat; injected seats never receive
them. While the session is locked, the lock surface is the only surface under the pen.

**Mapping (Niri):** with `map-to-focused-output` the active output, else the `map-to-output`
match; with an output the device's aspect ratio is kept (Mutter's rule, from `width_mm` and
`height_mm`) and the point is clamped one logical pixel inside it. Without one, the bounding box
of all outputs with no ratio correction, as OpenTabletDriver expects. Transform handling follows
the output.

**Pads:** wlroots' libinput backend never emits `attach_tablet`, and Sway and Mango pair pads with
tablets through libinput device groups, a C dependency the owner has ruled out. A pad follows the
most recently active tablet's tool instead: exact with one tablet; with several, a pad follows the
pen used last. This limit is recorded in the matrix.

**Config:** `input { tablet { … } }` decodes `off`, `map-to-output`, `map-to-focused-output`,
`left-handed` and `calibration-matrix`. The first three apply. The last two are libinput device
settings, unapplied for every device class today; they warn until the libinput-config work lands.

**Cursor:** a tablet-aware client's `set_cursor` sets the image while its tool is over the surface;
otherwise the default image.

## Files

- `internal/config/config.go` (+ test): the `tablet` section.
- `internal/wlr/tablet.go`: manager, tablet/tool/pad lifecycle, mapping, routing.
- `internal/wlr/input.go`: `handleNewInput` cases; `deliverPointerButton` keyed by a source pointer
  rather than `*wlr_pointer`, so the pen can press `BTN_LEFT`.
- `internal/wlr/faketablet.go`: fake tablet, tool and pad devices (cgo preamble, like `fakepointer.go`).
- `internal/wlr/testclient/toplevel.go`: optional tablet-v2 binding and counters.
- `internal/wlr/tablet_test.go`.

## Proof

1. Pure mapping checks against Niri's arithmetic: focused/named output with ratio correction,
   unified box without it, clamping, transforms.
2. `TestTabletToolFocusButtonsAndRemoval`: a tablet-aware window receives proximity, motion,
   tip and button; tip focuses it; the pad enters it and delivers a button; proximity-out leaves;
   removing the tablet and pad retires them.
3. `TestTabletEmulatesPointerForPlainClients`: a client without tablet-v2 receives pointer
   buttons from the tip, and the modal screenshot UI takes the tip as a click.
4. `TestTabletRespectsLockAndInjectedSeats`: locked, the window receives nothing; an injected seat
   never sees the tablet.
5. Config decoding, and the warning for the two unapplied settings.

Physical tablets are not available on the bench; the checks drive wlroots' own tablet objects
through fake devices. A real Wacom/Huion qualification stays a hardware limit.
