**5a: window opacity, a complete first change.**

1. Read pinned Niri `niri-config/src/window_rule.rs`, `src/window/mod.rs`,
   `src/layout/tile.rs::render_inner` and popup rendering. Determine parsing,
   clamping, fullscreen, popup and override behavior before choosing the Go field.
   Niri clamps resolved opacity to 0..1 for rendering and makes fullscreen opaque.
2. Add a named failing test in `internal/config/config_test.go` proving parsing,
   last-matching-rule precedence and default/no-match behavior. Reject malformed
   and non-finite values according to the pinned contract. Reuse `numberArg` or
   `boundedNumber` as appropriate; `floatArg` excludes its lower bound and cannot
   accept transparent opacity zero without a change in semantics.
3. Extend the existing rule/result structs and resolver. Keep warnings for other
   unsupported rule keys. Do not hide the whole block's warning after adding one key.
4. Add the compositor regression in `internal/wlr/window_rules_test.go`, using
   existing test clients and scene probes. Verify the actual buffer opacity,
   fullscreen entry/exit, state-rule changes, reload/removal restoring the default,
   and the interaction with opening and resize snapshots. Run it in CI lane 2.
5. Compose rule opacity with the existing animation opacity in `syncViewOpacity`;
   reuse SceneFX's opacity calls. Preserve popup semantics and snapshot alpha:
   `sceneFXSetTreeOpacity` walks every buffer, while cloned snapshots retain alpha.
   Check which popup trees the walk reaches before using it. Keep input hit testing
   and frame callbacks working for transparent and resizing windows.
6. Run the named config test locally, build/vet, then the hosted compositor check.
   Record exact test names and known differences in the config plan and matrix.

**5b: decoration overrides.** Read Niri's partial merge rules, then extend the
existing decoration types and render path for window focus-ring, border, shadow,
tab indicator and draw-border-with-background. Add missing global/workspace
appearance settings through the same ownership path. A rule that changes one
color must retain unrelated inherited fields. Test active/inactive/urgent state,
reload/removal, fullscreen suppression, workspace overrides and output moves.
Prefer consolidating existing parsers over copying separate versions. Keep
unsupported gradients/subkeys visible until implemented.

**5c: effects and layer appearance/privacy.** Apply window/layer background effects
through existing SceneFX machinery. Add layer opacity, shadow and corner geometry,
and layer `block-out-from`. Privacy needs capture-path evidence: protected pixels
must disappear from the intended captures while display pixels remain correct,
including subsurfaces, popups, commits, lock and reload. Reuse current privacy tests;
do not satisfy this by hiding the displayed layer.

Each part must parse, resolve, render, reload, and leave a runnable regression.
Keep #94 draft while it carries unfinished tranche work; refresh its title and
description to describe the actual scope before review/integration.
