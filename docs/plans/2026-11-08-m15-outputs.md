## 2. Niri's design, which sysc follows

Niri keeps one list of output configs. A config reload replaces it. `niri msg output` and
wlr-output-management edit it in memory (a transient change that the next reload undoes). Every
path then calls one function, `reload_output_config`, which:

1. finds each connected output's config: the first section whose name matches the connector,
   case-insensitively, or "make model serial", with "Unknown" for a missing field;
2. applies the scale (configured, or guessed from the physical size, then rounded to N/120) and
   the transform (the panel orientation plus the configured one);
3. lets the backend apply `off`, the mode and VRR (`pick_mode`: with a refresh rate, only an exact
   match in mHz; without one, the highest refresh rate at that size; `custom=true` computes a CVT
   mode; otherwise, the preferred mode with the highest refresh rate);
4. repositions every output: outputs with a configured position first, unless it overlaps an
   already placed output; then the rest, left to right, sorted by make, model, serial and
   connector;
5. applies per-output `backdrop-color`, `layout` (merged over the global layout) and
   `hot-corners`, and tells wlr-output-management that the config changed.

sysc gets the same shape: one `applyOutputConfigs` on the compositor thread that every path
calls. Each output's change is a single `wlr_output_state`, tried with `wlr_output_test_state`
before it is committed. A failed test falls back the way Niri does (the preferred mode). A failed
commit leaves the output in its working state and is reported, never half-applied.

## 3. Slices

Each slice lands with its tests, the matrix rows and an execution record here. The
lane-2 tests use headless outputs added to the running compositor (`addHeadlessTestOutput`).
Headless outputs take any custom mode, so mode, scale, transform and position changes can be
tested next to the vkms output.

### Slice 1: the `output` section and the apply engine

- Parse `output "<name>" { … }` with Niri's keys: `off`, `mode` (with `custom=true`), `modeline`,
  `scale`, `transform`, `position x= y=`, `variable-refresh-rate on-demand=`, `focus-at-startup`,
  `background-color` (deprecated, folds into the per-output layout), `backdrop-color`,
  `hot-corners` and `layout`. A malformed value is an error, as in Niri. Keys that a later slice
  applies keep warning by name (`output.layout`, `output.hot-corners`, `output.backdrop-color`,
  `output.modeline`).
- `applyOutputConfigs`: mode, scale, transform, `off`, VRR on or off, and Niri's repositioning.
  It runs when an output connects and after a config reload. An output turned `off` leaves the
  layout as an unplugged one does, and its workspaces come back when it is turned on, as Niri's
  do.
- `focus-at-startup` picks the focused output at startup.
- Tests: config parse and name matching (pure); in lane 2, mode, scale, transform and position
  on headless outputs; a mode the output lacks falls back to the preferred mode; an overlapping
  position falls back to automatic placement; `off` and back on keeps the workspaces; a reload
  re-applies; workspaces, layers and the pointer follow the new geometry.

### Slice 2: the `Output` request and `msg output`

`OutputAction` (`Off`, `On`, `Mode`, `CustomMode`, `Modeline`, `Scale`, `Transform`,
`Position`, `Vrr`) through IPC and `sysc-compositor msg output`. It edits the in-memory config,
as `modify_output_config` does (adding a section if none matches), then calls the engine. A reload
drops the change.

### Slice 3: `zwlr_output_manager_v1`

wlroots' `wlr_output_manager_v1` helper publishes the heads from the current state. `test` runs
the engine's test path only; `apply` edits the in-memory config and calls the engine, as Niri's
`output_management.rs` does. Wire the `zwlr_output_power_manager_v1` global here as well. Tests:
a protocol client in `testclient`, plus `wlr-randr` if lane 2 can install it.

### Slice 4: DisplayConfig apply

`ApplyMonitorsConfig` on `org.gnome.Mutter.DisplayConfig` (`internal/session/display_config.go`)
maps onto the same edit and apply. Method `verify` only tests; `temporary` and `persistent`
both apply transiently, because sysc never writes the user's config.

### Slice 5: VRR on demand, per-output layout, backdrop and hot corners

- `variable-refresh-rate on-demand=true` turns VRR on only while a window whose rule sets
  `variable-refresh-rate true` is on that output, as Niri does (`sysc-2265`, which also takes
  the window-rule key out of the warnings).
- Per-output `layout` merges between the global layout and a workspace's, Niri's order;
  `backdrop-color` and `hot-corners` per output.

### Slice 6: mixed DPI, hotplug and renderer loss

- Mixed DPI: the pointer image, screenshots, the screenshot UI, lock surfaces, capture and touch
  and tablet mapping on two outputs at different scales and transforms.
- An unplugged (or `off`) output's whole workspaces move to the focused surviving output,
  preserving IDs, columns and floating bounds, and return on reconnect. The owner chose
  Niri's behavior on 2026-11-08. Keep detached workspaces when no output remains.
- Unplug and replug with configured outputs; the owner's two-monitor layout in the session VM
  (two virtio heads) or on the desktop with consent.
- Renderer loss (GPU reset): recreate the renderer and allocator, re-init every output's render
  state and the scene's textures, as Niri's `TtyRenderer` recovery does. Prove it with
  SceneFX + llvmpipe (`WLR_RENDERER=gles2 LIBGL_ALWAYS_SOFTWARE=1`) under vkms against a
  forced loss in a test. The owner approved this replacement on 2026-11-08: SceneFX
  aborts on a Pixman render pass.

## 4. Owner decision

Scale for an output the config does not set:

- Niri guesses it from the physical size and resolution (`guess_monitor_scale`); Hyprland's
  default rule (`monitor=,preferred,auto,auto`) also picks one from the pixel density; Mango uses
  1. sysc uses 1 today.
- Taking Niri's guess changes the look of every output the config does not name, such as the
  laptop's eDP-1. Configured outputs keep their configured scale either way.

**Decided 2026-11-08: Niri's guess.** sysc ports `guess_monitor_scale` and rounds the result to
N/120, as Niri does.

## 5. Rules

- Presentation stays vsynced. VRR changes the refresh timing, never tearing; a tearing hint
  never authorizes tearing (owner decision, M12).
- No sysc-only config nodes: the KDL contract is Niri's.
- An unsupported or failing change keeps the working configuration and is reported (IPC reply,
  protocol `failed`, D-Bus error); never a half-applied output.
- Never `go test ./...`, never `-race`; nested tests in the laptop session VM only.

### Slice 6, 2026-11-08/09

- Unplug/disable moves workspaces intact and reconnect restores them. With no outputs, IPC
  retains detached workspaces and windows; closing a detached window does not resurrect it.
- Screen and portal PNGs and screenshot selections keep transformed outputs upright. The
  screenshot UI closes on output retirement or geometry change. Raw capture protocol frames
  retain their existing orientation contract.
- Renderer loss queues one recovery on the compositor thread, recreates SceneFX and its
  allocator, reinitializes output rendering, reimports textures and damages the scene.
  SHM submissions retain their latest pixels, including cached subsurface commits; DMA-BUF
  recovery retains importable sources. An unrecoverable buffer ends the session with an error.
- Intentional ceiling: SHM backup copies the full submitted buffer, up to 64 MiB per buffer.
  Damage-region copies are the upgrade path if this costs too much for SHM-heavy clients.
- Proof: workspace migration/reconnect and zero-output model tests;
  `TestMixedDPIOutputsKeepScreenshotsAndTouchUpright` uses a rotated scale-2 headless output
  beside vkms and checks pointer-theme scale, touch coordinates, PNG dimensions and selection
  pixels; existing lock, tablet and capture regressions cover their routing paths.
  `TestRendererLossRecreatesAndRepaintsExistingBuffers` restores static wallpaper under
  SceneFX + llvmpipe; `TestRendererLossRestoresLatestSHMCommit` restores the latest green
  frame after a red-to-green update.
- These checks force renderer loss in software. They do not qualify a physical GPU reset,
  hardware VRR, or the owner's two-monitor desktop/two-virtio-head session layout.
