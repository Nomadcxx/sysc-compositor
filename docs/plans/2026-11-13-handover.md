## Implemented parity work

1. **`sysc-2280`, workspace switches.** Keyboard switches and swipes share output
   offsets and a 10% output-height gap. Reuse overview's lower-layer projection
   at zoom 1. Clip projected buffers, translate input, and mask foreign output
   nodes during physical repaint and capture. Tests cover all eight transforms,
   cached SceneFX buffers, moving bottom-layer input and vertically stacked outputs.
2. **`sysc-2281`, workspace shadows.** Reuse `config.Shadow` and SceneFX, with
   Niri defaults and output-height/1080 × zoom normalization. Reject window-only
   shadow fields and skip empty dimensions from extreme negative spread.
3. **`sysc-2282`, insert-hint gradients.** `internal/config/gradient.go` validates
   Niri's gradient fields. `internal/ui/gradient.go` renders premultiplied
   interpolation through the existing image buffer. Crop to the visible hint and
   keep the 64 MiB allocation bound. Removing the gradient restores solid color.
4. **`sysc-2283`, DND workspace scrolling.** Extend the existing timer and model
   gesture path: dwell, 1500 pixels/workspace, no momentum/rubber band and immediate
   reversal at the ends. Use the native drag's touch finger, preserve it through
   overview opening, validate native pointer/touch serials, position the drag icon,
   retarget projected windows as the strip moves and cancel on lock.
5. **`sysc-2284`, debug non-session D-Bus.** `StartDBus(sessionMode bool)` allows
   the flag to start ordinary services outside session mode. Environment activation
   and ServiceChannel remain session-only, including the manual-reply interceptor.
6. **`sysc-2285`, PipeWire modifier.** Source review found MemFd-only RGBA casting
   without a DRM modifier. Niri's flag filters DMA-BUF formats; this backend has no
   list to filter. Document the flag as a no-op for this transport and remove its
   warning. No DMA-BUF casting support is claimed or added. The existing cast test
   now runs with the flag off/on; its receiver requires modifier-free negotiation
   and MemFd buffers. Focused local review found no issues.

Important implementation evidence:

- SceneFX can release `buffer->buffer` after upload. Crop using cached
  `WLR_PRIVATE.buffer_width/height`, with the inverse buffer transform. Pixel
  regressions established the direction; do not reverse it from intuition.
- Keep `overview.go` on stock `<wlr/types/wlr_scene.h>` and `insertHintImage` as
  `unsafe.Pointer`. Mixing concrete SceneFX/wlroots structs across cgo files causes
  inconsistent struct definitions.
- Installed wlroots 0.20.2 `drag_handle_touch_up` dereferences `drag->source` on
  **every** touch up (the 0.20.0 tag only did so over an empty target). A
  NULL-source intra-client drag is valid, and wlroots' pointer path ends one
  without a drop, so `handleTouchUp` cancels every source-less touch drag before
  forwarding up. Ending all touches also cancels a native touch drag. The drag
  finger keeps its touch point after its origin surface goes, so its motion and
  up still drive the grab. Clear both the seat's touch focus and the touch point's
  focus for empty targets. `TestNativeTouchDragEndsAfterItsSurfaceIsGone`
  reproduced the stuck grab and the SIGSEGV.

## Lid policy (`sysc-2286`), done

The compositor owns the lid state: `handleSwitchToggle` and login1 (through the
server) call `SetLidClosed`, which reapplies the output config when the value
changes, as Niri's `set_lid_closed`. `outputOff` is the one predicate for config
off or Niri's derived policy (`shouldDisableLaptopPanels`: lid closed, debug flag
off, a non-`eDP-`/`LVDS`/`DSI-` connector connected, config-off ones included).
It feeds reload, strict IPC/output-management preparation and apply, hotplug, and
unplug (the destroy handler reapplies when the policy result changes, before the
nested-backend terminate check). Config is never rewritten. `adoptOutput` keeps an
output that connects or returns during PowerOffMonitors dark, as Niri does; that
rule moved there from `handleNewOutput`. The debug flag no longer warns; there is
no unapplied debug key left. Tests name a headless output `eDP-1` before the
compositor hears of it (`addNamedHeadlessTestOutput`), never renaming a published
output. `TestLidPolicyTurnsLaptopPanelOffOnlyWhileExternalOutputExists` failed with
the policy neutralised and passes; `TestLaptopPanelPolicyMatchesNiri` is pure.

Residual: a lid change that arrives while the session is inactive (VT switched
away) applies immediately and may fail on DRM; Niri defers it to resume. Reload
has the same pre-existing gap; no resume reapply exists yet. A per-output DPMS-off
set by a power-management client (not PowerOffMonitors) is not remembered across
a lid cycle; Niri has no per-output power state to match.
