## Working rules (unchanged, all binding)

The 2026-11-14 handover's rules stand. In short:

- One package, explicit test names:
  `timeout 90s env GOMAXPROCS=2 go test -count=1 <pkg> -run '^(…)$'`.
  Never `go test ./...`, never `-race`.
- Tests that build a compositor skip unless `SYSC_NESTED_TESTS=1`. Set it only
  with the owner's consent for that run, never in a loop, script or background
  job. Laptop runs are pre-approved; the owner's desktop is not.
- `runtime.LockOSThread()` before wlroots calls; Go + cgo only, no `.c`/`.h`.
- `go generate ./internal/wlr` once per fresh tree.
- **No AI attribution anywhere** (commits, PRs). The global commit hook also
  rejects substrings such as "both", "bot", "agent", "cursor".
- Laptop gate builds keep the basename `sysc-compositor` (`sysc-2261`).
- bd runs from `/home/nomadx/sysc-shell`; worktree commits there need
  `BEADS_DB=/home/nomadx/sysc-shell/.beads/beads.db`. This repository has no bd
  database.
- Other sessions work this repository at the same time. Check open PRs and
  message the active sysc-compositor session before touching shared files.

### 3. SceneFX blur culling, `sysc-2303` (P2): owner decision

SceneFX 0.5 culls the background clear under opaque nodes. A blur node below
an opaque node then samples old swapchain contents and bakes them into pixels
nothing damages again. SceneFX `main` behaves the same way. The only lever in
sysc is `WLR_SCENE_DISABLE_VISIBILITY=1` scene-wide, which costs occlusion
culling, direct scan-out under fullscreen and frame-callback throttling.
archThink's arrangement does not hit it, since its only blur is the bar's.

Options for the owner, recommended first:

1. Report it upstream with the lane-2 reproducer (frosted windows beside
   opaque ones, committed-buffer readback) and propose keeping the clear within
   a blur's sampling distance. Carry nothing in sysc meanwhile.
2. Turn visibility off only while a blur node is visible, at the costs above.

Do not ship a SceneFX fork without the owner's approval.

## Recipes and traps learned this round

- **Nested runs need #116.** Any build without it fails `Swapchain for output
  'WL-1' failed test` and maps nothing, on any Wayland host.
- **A bare `go build` needs `CGO_CFLAGS_ALLOW=-fno-strict-overflow`.** The
  Makefile exports it.
- **Headless test run on the laptop** (from a dirty tree):
  `tar -C "$WT" --exclude=.git --exclude=internal/wlr/protocols -czf - . | ssh -p 7777 nomadx@192.168.0.64 'd=$(mktemp -d); trap "rm -rf $d" EXIT; tar -C $d -xzf -; cd $d; go generate ./internal/wlr; timeout 300s env -u WAYLAND_DISPLAY WLR_BACKENDS=headless WLR_HEADLESS_OUTPUTS=1 SYSC_NESTED_TESTS=1 XDG_RUNTIME_DIR=/run/user/1000 GOMAXPROCS=2 go test -count=1 ./internal/wlr -run "^(Name)$" -v'`.
- `TestBackgroundColorFillsTheOutputBelowTheBackgroundLayer` and
  `TestWorkspaceSwitchMovesBackgroundAndBottomLayersWithGap` failed headless on
  `cc77dcd` before any of this round's changes. Recheck them on current main
  before reading a failure as a regression.
- `testclient.StartLayerPopupClient` needs a seat pointer first
  (`c.addFakePointer()`).
- **Nested live check:**
  [assets/2026-11-18-handover/nested-layer-check.sh](assets/2026-11-18-handover/nested-layer-check.sh)
  runs a build nested in the laptop session with a Top-layer waybar and a
  kitty, drives fullscreen and overview over IPC, and shoots each step with
  grim. To compare against a baseline, build both binaries into one temp dir,
  each on a tree that contains #116.
- **Top-layer stacking** (#117): `rendersAboveTopLayer` mirrors niri's
  `render_above_top_layer` (a mapped, visible fullscreen window on the output,
  no overview, no workspace switch). `syncTopLayerStacking` runs in the frame
  listener before the repaint and moves that output's Top surfaces into
  `topUnderFullscreen`, a tree placed just above the lower layers and below
  the windows. Keyboard focus follows: a fullscreen window precedes Top
  on-demand and exclusive surfaces, but not Overlay.
